Custom tactile sensors, wrapped around any real part

OpenTactileCAD designs custom piezoresistive tactile sensor arrays — for robot grippers, prosthetic hands, wearables, or any surface that needs to feel contact — and turns them into a fully routed, manufacturable PCB: sensor pixels, wiring, connector, DRC-checked routing, and KiCad/Gerber files, generated automatically from a shape you draw, import, or scan. No PCB design experience required.

New here? Four words cover almost everything:
Taxel
one pressure-sensing spot — a "touch pixel". A sensor is a grid of them, like camera pixels for touch.
Pitch
the spacing between taxel centers. Smaller pitch = more taxels packed into the same shape.
Cable edge
the edge of your shape (shown orange) where a flat ribbon cable exits to plug into your electronics.
DRC
design-rule check — an automatic inspection that confirms no wires touch or run too close. 0 violations = manufacturable.

Two more ways to use OpenTactileCAD

Run it on your own computer — much faster

This website runs on a free server that falls asleep when idle, so your first Generate of the day can wait up to a minute for it to wake. The exact same app runs locally with none of that — designs generate in a second or two, and your shapes never leave your machine.

  1. Install Python 3.12 or newer from python.org. On Windows, tick "Add python.exe to PATH" in the installer.
  2. Download the code: on the project's GitHub page, click the green Code button → Download ZIP, and unzip it anywhere (or git clone it if you use git).
  3. Open the unzipped folder and double-click Start_OpenTactileCAD.bat (Windows) or Start_OpenTactileCAD.command (Mac). The first run installs what it needs into its own private folder — a few minutes, one time only. After that it starts in seconds and opens this same app in your browser.

Mac: if double-clicking is blocked, open Terminal, type bash  (with a trailing space), drag tactile-pcb-web/start_local.sh onto the window, and press Enter.

Or describe your sensor in plain English

The project includes a skill for Claude Code (Anthropic's AI coding agent). Instead of drawing anything, you describe the sensor — "a tactile sensor shaped like a size-9 shoe insole with the cable at the heel" — and it works out real dimensions, builds the outline, runs this same design pipeline on your computer, and hands back the finished manufacturing files.

  1. Do steps 1–2 on the left (install Python, download the code).
  2. Install Claude Code from claude.com/claude-code.
  3. Open a terminal in the downloaded folder and run claude.
  4. Describe the sensor you want, in your own words. Mention the shape, the size, and where the cable should come out — it will ask about anything else it needs.

Good for shapes that are easier to describe than to draw — an insole, a glove fingertip, a sensor matched to a part whose drawing or 3D model you already have (it reads DXF and STL files too).

Getting a board shape

Every design starts the same way: get a closed 2D outline into the Board Outline canvas. There are three ways to do that — mix and match, or switch mid-project using the Mode switcher.

Draw

Use the Line, Rectangle, H/V, and Arc tools to sketch your outline directly. When you're done, select the edge where the connector tail should exit and click Set cable edge (it turns orange) — Generate is blocked until this is set, so a stray first stroke can never silently become the connector edge. This isn't just freehand: select a vertex or edge and type an exact Length and Angle in the fields above the canvas to dimension it precisely, like a real CAD program.

DXF

Upload a closed 2D outline exported from AutoCAD, Fusion 360, or similar CAD tools. We automatically pick the largest closed shape in the file (in case it contains extra reference geometry) and scale it to millimeters using the file's unit metadata. A DXF outline has no inherent cable edge — confirm or change it with Set cable edge after import.

STL

Upload a 3D model, then click a face (or several connected faces, or a smoothly curved patch) to select the surface your sensor will cover — or use Draw patch to click points directly on the surface and outline your sensor by hand, letting the app smooth away texture like tread patterns. Unfold selection flattens the result into a 2D outline using a true-scale unfolding algorithm — like unwrapping a physical piece of paper from the part. The result lands in the same Board Outline canvas, where you can still hand-edit it. Like a DXF import, an unfolded outline has no inherent cable edge — confirm or change it with Set cable edge once it loads.

If your selection spans surfaces that don't share a mesh edge (say, a fingertip's front face plus its two sides), the button changes to Join surfaces… and the viewer walks you through the join, one cut at a time: it shows numbered marker dots along each surface's boundary, and you click two matching corner pairs — "this corner attaches to that one" — for each cut. Only after every cut is resolved does the 2D preview appear, with Use this shape handing it to the outline canvas. Picking the corners yourself is deliberate: you can see the real part, so you know which corners truly touch.

Sensorize zone

The sensorize zone is an optional second shape you can draw inside your board outline. It constrains where sensor pixels get packed — it does not change your board's outer edge, connector, or routing bounds.

Use it when only part of your board should be sensing area — for example, leaving a clear margin around a mounting hole, or concentrating sensors on a fingertip while leaving the rest of the outline as structural board.

To use it: draw a board outline first (the toggle unlocks once you have one), switch the toolbar target to Sensorize zone, and draw a smaller shape with the same tools. It renders as a dashed green overlay so it's never confused with the board outline.

Parameters glossary

Most parameters are straightforward (pixel size, spacing, trace width). Two groups deserve more explanation: the pixel footprint (what each individual sensor looks like) and board sizing (four related but distinct mechanisms for making room for the wiring that connects every sensor pixel to the connector).

Sensor grid: size or count

The sensor grid can be specified from either end:

Set taxel size
You give Pixel W/H and Pitch X/Y; how many fit is whatever your outline allows. The original behaviour.
Set rows & columns
You give the grid you want and the taxel size needed to fit it is calculated from your outline (its bounding box, minus the edge keepout, divided by the requested counts). Pitch is set equal to the taxel size, so taxels tile edge to edge with no gap. On a non-rectangular outline the taxel size is shrunk in small steps until the requested rows and columns really pack — corners that fall outside the shape are still dropped, so you may get slightly fewer taxels than rows × columns. Available in Grow board to fit wiring mode only: with the outline fixed, the packable area depends on the wiring keep-out band, whose width depends in turn on the row/column counts you are trying to set.

Pixel footprint

Each sensor "pixel" is a pair of interdigitated copper electrodes — two interleaved comb-like patterns. A piezoresistive material laminated over the top bridges the fingers, so its resistance drops measurably under pressure. The live preview in the Parameters panel shows exactly what one pixel's electrodes look like as you adjust these:

Pixel edge clearance (edge_clear_mm)
Gap from the pixel's own outer boundary to its fingers. Not the same as Edge keepout above, which is a board-level margin from the outline — this one is local to a single pixel's footprint.
Pixel center clearance (center_clear_mm)
How far each finger reaches toward the opposite pad before stopping, controlling the gap down the pixel's center line.
Via drill / diameter (via_drill_mm / via_dia_mm)
The plated hole connecting a pixel's top-layer pad to its routed trace underneath.

Board sizing

Grow board to fit wiring (board_mode: "expand")
The default. Sensors are packed at maximum density inside the shape you drew, then the final board outline is grown outward until every wire fits. No sensor is ever dropped — but the exported board is larger than the shape you drew.
Keep outline fixed, shrink sensor grid (board_mode: "fixed_keepout")
The shape you drew is exactly the board you get. A wiring keep-out band is reserved just inside the outline — wider on the sides that carry more wires, narrow at the top where few pass — and only the area left over is filled with sensors, so pixels that would reach into the wiring zone are never placed. Because the keep-out is a clean geometric band, the surviving sensors stay a regular rectangular grid rather than a shape with holes punched in it. The band is sized from the actual wiring demand and the result is DRC-verified, falling back to a more conservative band if the dense one does not route cleanly. Trade-off: still fewer sensors than grow mode on the same outline.
Routing margin (routing_margin_mm)
The minimum wiring space (mm) reserved on each side before routing starts; the actual amount is sized automatically from how many sensors need wiring out on that side. In grow mode this space is added outside the outline; in fixed mode the same estimate is carved inside it.
Post-route safety net
Not a setting you control directly — after wires are actually routed, if any wire still pokes outside the board, the board is grown just enough to contain it. A safety net on top of Routing margin.
Follow layout/routes (follow_main_padding)
Instead of a boxy expanded rectangle, shrink-wraps the final board edge to hug the actual sensor grid and wire bundles — a more organic, compact final shape.
Follow padding (follow_main_padding_mm)
How much space (mm) to leave between the outermost wire/sensor and the shrink-wrapped edge.
Smooth follow edge (smooth_follow_padding)
Rounds that shrink-wrapped edge instead of leaving sharp mitered corners.
Tail extension
A separate, later step — after you Generate, the PCB Preview toolbar lets you draw a custom path for the cable/connector tail, growing the board along that path.

Route editing

After Generate, the PCB Preview toolbar lets you fine-tune the routed board:

  • Undo / Reset route / Reset all — step back or discard route edits.
  • Redo padding — recompute the board's outer padding after edits, without re-running the full router.
  • Tail extension — draw a custom path for the connector's cable/tail instead of a straight edge.
  • Chamfer — cut sharp corners on routed traces to a given size.
  • Check DRC — re-run the design-rule check (clearance/crossing/board-edge violations) on the current routes.

Exporting

The downloaded ZIP contains manufacturing files you can send to a PCB fab, or open in KiCad:

  • A .kicad_pcb board file and pixel/connector footprints.
  • Gerber files (the industry-standard format PCB fabs use).
  • An Excellon drill file for vias.
  • A JSON manifest describing pixel placements, useful for driving the sensor from a microcontroller.

The connector is auto-selected as the smallest 0.5mm-pitch FPC connector (20 up to 100 positions) that fits your sensor's row and column count. If you need a specific larger size — say, to slot into an existing readout board — a "Need a bigger connector?" control appears next to the stats after Generate, offering larger sizes up to 100-pos.

A bigger connector body can be wider than the cable/tail running into it, which puts a step in the board's cut outline. Shoulder fillet, next to that control, rounds that step — both the outward corners at the connector tip and the two inward notches where the tail meets the shoulder — instead of leaving sharp 90° corners that concentrate stress in a flex PCB. Set it to 0 for square corners.

FAQ / troubleshooting

"No pixels packed" / similar errors on Generate
Your outline is too small for the current pixel size, pitch, and edge keepout. Draw a larger outline or reduce those parameters.
"Sensor fill region does not overlap the board outline"
The sensorize zone you drew is fully outside the board outline — make sure it's drawn inside the outline shape.
"No closed outline found — check for gaps or open ends" (DXF import)
The DXF file doesn't contain one clean closed loop of geometry — check for gaps, unconnected segments, or stray extra shapes in the source file.
"backend: unreachable"
The backend server isn't responding. If this is a hosted deployment, it may be waking up from an idle sleep — wait a few seconds and reload.
